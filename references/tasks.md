# 任务草稿与平台创建

编写DDL、转换SQL、调度与命名时读 [数仓任务规范](task-conventions.md)；涉及销售等业务口径时读 [业务规则](business-rules.md)。历史模板与已核验平台能力分别标记。

## 当前能力边界

已验证任务详情/源码的只读查看；尚未验证本项目平台任务创建、保存、发布、上线、回填的完整接口合同。技能能准备任务草稿，并指导在授权后通过真实UI发现和核验创建流程；不提供猜测的createTask API或伪称已经自动化验收。

用户要“整理创建任务规则”只需交付规则。用户要“为某目标创建任务”则先准备具体任务定义；在授权覆盖的范围内完成页面创建。创建不自动包含运行、发布、调度上线、历史回填、删改原表。

## 本地可审核任务定义

按实际需求创建独立任务目录，包含以下已确认内容；不清楚的值写UNKNOWN并说明需要什么证据：

- 任务名称、所属开发组、负责人、引擎、用途。
- 源表/目标表全名、原生ID、目标粒度、字段映射及所依据的知识包SHA/版本。
- 分区键、分区值和业务日期、增量/全量方式、去重键、重跑幂等性。
- SQL草稿：DDL与转换SQL分开；未经授权不提交写语句，原表不覆盖，过程/结果表另建。
- 调度周期、时区、依赖、数据就绪条件、失败告警、资源预期；用户没要求调度时不擅自启用。
- 验证计划：结构匹配、主键/粒度、空值、重复、金额/数量对账及预期范围。
- 明确的动作状态：DRAFT / CREATED_READBACK_VERIFIED / RUN_NOT_REQUESTED / PUBLISH_NOT_REQUESTED；未发生的步骤不能标完成。

不要为了填满模板发明目标库、任务ID、调度时间或负责人。可以将已有SQL中的写语句作为证据读取，但不能因此执行。

## 授权后的页面操作

先确认当前账号/开发组、名称是否已有、源表权限及目标范围。通过可见UI观察真实表单、校验、保存响应和任务版本；不得猜API路径、必填字段、枚举、签名或ID。使用当前可用的浏览器工具，并遵守该工具的操作约束。

将即将提交的具体任务定义交付用户可审核。只有当前会话授权已覆盖这一定义和动作时才提交；若还需确认，确认作为完成准备后的最后一步。成功后读回任务ID、名称、组、版本、SQL指纹及发布/调度状态。没有读回证据时标UNKNOWN_SAVE，不盲目重试创建。

修改已有任务前保留原定义与版本，说明差异。生产运行、发布、上线或回填按明确目标和范围执行，不能将创建权限扩成这些权限。源端响应改变身份/权限合同或出现需要绕过权限的情况时停止该动作并报告。
