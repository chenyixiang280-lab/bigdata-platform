# 查询规则

## 从结构到SQL

1. 明确问题、目标粒度、时间范围、组织口径和输出上限。先读取目标表及关联表的字段、分区和已有来源。
2. 使用完整库表名，必要字段明确列出。相似表名或热度较高仅是候选，不能替代准确匹配。
3. 分区列与业务日期分开；不因字段名像日期就认定是分区。使用已确认的类型和分区范围，时间范围优先明确半开区间。
4. 核对Join两侧键、关系与粒度；防止维表重复放大。事实只有内部ID时通过维表取得业务编码，不能直接改名冒充。
5. 汇总前确认退货、补贴、店转、自营/加盟、税费和金额单位；未确认毛利字段或成本口径时先不算毛利。
6. 缺失与零分开，未知值保留理由。子店同期没有记录不自动视为异常，不补父店金额；单店无同期不计算同比。

## 本项目已确认的约定

- 默认Spark SQL。Spark平台请求值为`antspark`；UI Presto对应`trino`。平台请求值是曾验证的适配事实，现场变化需重新核实。
- Spark标识符按其方言使用反引号；Trino按其方言使用双引号，不混用函数和日期格式。
- 门店业务编码`shop_code`、名称`shop_name`；事实只有`dept_id`时经维表映射。有效`parent_shop_code`用于父子店关系。
- 当前管理范围回看与历史组织/同店可比不同。只有用户指定当前口径时，才以同一固定组织快照回看两个时期；不能自动把历史任务的T-1变成所有查询的规则。
- 对业务明细的探索默认每张表最多50行，且必须有适用的明确业务读取授权。LIMIT不代表底层扫描便宜，应同时加已核对的分区过滤。

这些字段和业务约定来自当前项目；跨企业复用时按新项目证据调整，不能泛化为数据库标准。

## 真实查询与导出

技能安装不授予平台访问权限。读取元数据的授权不覆盖SELECT、导出或任务写入。当前请求已明确授权的动作可继续，不逐次重复询问。

执行路径只允许单条SELECT或WITH…SELECT，使用项目现有SQLSafetyGate；不把CREATE/INSERT/UPDATE/DELETE等草稿送入查询执行路径。该门禁不是完整SQL语义/权限验证器。

使用项目已验证的BrowserContext/页面查询适配器。`jobId`必须来自本次`checkSql.response.data`，原样用于本次`executeSql`；不复用历史ID。不能假设普通CLI全部现场验收通过，也不能用本地模拟或旧导出任务证明本次成功。

提交后的超时可能意味着任务已经创建；先只读核对本次SQL、时间、新任务ID/批次，结果不确定时不直接重发。导出只有在当前范围和行数另获授权时执行，签名URL仅短暂存在内存。检查结果身份、字段、完整行数、截断标记与文件哈希，业务行不进入技能仓库。

无需真实数据即可完成的任务，交付可核验SQL及口径，不为了“验证”自行执行。
